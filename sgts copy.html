Sistema de Gestión de Tickets de Soporte (SGTS)

Aplicación web empresarial orientada al registro, seguimiento, asignación y control de solicitudes de soporte técnico con arquitectura en capas y separación estricta de responsabilidades.

Ver Arquitectura Repositorio GitHub

Pila Tecnológica Principal

  • Plataforma: .NET 10 / C#
  • Presentación: ASP.NET Core MVC, Razor Views, Web API
  • Base de Datos: SQL Server con EF Core 10
  • Seguridad: Cookie Auth (MVC) & JWT Bearer (API)
  • Validación y Pruebas: FluentValidation, xUnit, Moq

Propósito y Dominio Funcional

¿Qué resuelve SGTS?

SGTS centraliza la gestión operativa de mesas de ayuda corporativas. Permite ciclo de vida completo de tickets: creación, asignación a técnicos especializados, control de estados e historiales de prioridad, comentarios de seguimiento y gestión de archivos adjuntos asociados.

El sistema combina una interfaz web interactiva con endpoints de API protegidos, organizando la lógica empresarial en componentes independientes y testeables.

Arquitectura de la Solución

Arquitectura en capas (Layered Architecture) con separación modular de responsabilidades. 

Usuario 
  ↓
SGTS.Web (MVC / API Controllers / Middleware / Razor / JS / CSS)
  ↓
SGTS.Business (Servicios de aplicación, validaciones de negocio, AutoMapper)
  ↓
SGTS.Persistence ───→ SQL Server (EF Core 10, Repositorios, Configuraciones)
  │
  └───────────────→ SGTS.Infrastructure ───→ JWT / Password Hashing / File Storage

SGTS.Web

Entrada HTTP, controladores MVC y de API, vistas Razor, middlewares de manejo de errores, filtros y recursos estáticos modulares.

SGTS.Business

Capas de servicio, reglas de negocio centralizadas mediante validadores específicos, mapeos con AutoMapper y gestión de identidad.

SGTS.Persistence & Infrastructure

Acceso a datos con EF Core 10, migraciones, patrones de repositorio, hashing seguro de contraseñas y almacenamiento físico de archivos.

Patrones y Prácticas de Ingeniería

Repository & Service Layer

Encapsulamiento de datos mediante interfaces específicas y servicios coordinadores de lógica de aplicación.

Dependency Injection

Registro modular por extensiones (`AddBusiness`, `AddData`, `AddInfrastructure`) con ciclos de vida controlados.

DTO & Data Mapper

Desacoplamiento estricto entre entidades de persistencia y contratos externos usando AutoMapper.

Soft Delete + Query Filter

Borrado lógico de tickets mediante banderas de activación con filtros globales automáticos en EF Core.

Middleware Global

Captura centralizada de excepciones transformadas en respuestas HTTP estandarizadas por `ErrorCode`.

Guard & Options Pattern

Extensiones `EnsureFound` para comprobaciones rápidas y configuración fuertemente tipada de almacenamiento.

Seguridad, Autenticación y Autorización

Autenticación Híbrida

  • Cookie Authentication: Generación de identidades mediante claims para vistas MVC.
  • JWT Bearer: Tokens seguros validados en firma, issuer, audience y expiración exacta (clock skew cero) para la API.

Autorización y Permisos

  • Políticas HTTP: Restricciones por roles como PersonalTecnico, SoloSupervisor y SoloAdministrador.
  • Permisos de Negocio: Validación granular mediante `Permission` y `RolePermissions`.
  • Contexto Actual: Componente `CurrentUser` para extraer identificadores y roles directamente desde los claims.

Persistencia y Manejo de Archivos

SQL Server & EF Core 10

Centralización de esquemas mediante `AppDbContext` y configuraciones desacopladas con `IEntityTypeConfiguration<T>`. Relaciones explícitas de 1:N para historiales de estado, prioridad y asignaciones de técnicos.

Almacenamiento Físico de Archivos

Para evitar saturar la base de datos con blobs binarios, `FileStorageService` almacena los documentos físicamente organizados por directorios de ticket, asignando nombres seguros basados en GUID y guardando metadatos relacionales en SQL Server.

Frontend Modular y Pruebas Automatizadas

Organización Frontend

Estructura limpia orientada a mantenimiento:

  • JavaScript: Separado en carpetas de infraestructura, servicios, componentes, páginas y auth.
  • CSS: Organizado modularmente en base, layout, componentes y páginas.

Pruebas Automatizadas

Garantía de calidad mediante:

  • Frameworks: xUnit para ejecución y FluentAssertions para aserciones legibles.
  • Mocking y Aislamiento: Uso de Moq para servicios y EF Core InMemory para pruebas de repositorios.
